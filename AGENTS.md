## Доступ к данным frontend

- Каждый бизнес-модуль обязан использовать единый поток: `UI → TanStack Query hooks → Repository interface → MockRepository или ApiRepository`.
- Страницы, компоненты и hooks не должны импортировать mock-массивы, fixtures или вызывать `fetch` напрямую.
- Типы и Zod-схемы запросов/ответов хранить в `packages/contracts` и использовать одновременно в mock и API реализациях.
- `MockRepository` должен реализовывать тот же интерфейс и поведение, что будущий `ApiRepository`, включая асинхронность, ошибки и CRUD-операции.
- `ApiRepository` отвечает за HTTP, проверку статуса ответа и Zod-валидацию данных.
- TanStack Query отвечает за загрузку, кеш, loading/error состояния, mutations и invalidation.
- Выбор mock/API реализации выполнять только в dependency-binding файле модуля. Для подключения backend UI, страницы и hooks не переписывать.
- Все новые модули создавать сразу по этому шаблону. Существующий Dashboard позднее перевести на `DashboardRepository` до подключения его реального API.
