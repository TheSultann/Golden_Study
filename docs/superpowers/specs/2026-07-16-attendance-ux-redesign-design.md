# Attendance UX Redesign Design

## Цель

Сделать `Davomat` быстрым ежедневным журналом: сотрудник выбирает группу и дату, последовательно отмечает учеников и сохраняет изменения без лишнего скролла и визуального шума.

## Диагноз

- В `index.css` одновременно действуют несколько базовых и mobile-правил для `.attendance-*`.
- Четыре определения `.attendance-actions` конфликтуют по `position`, `padding`, `margin`, направлению flex и mobile-поведению.
- Mobile использует desktop-таблицу, превращённую в карточки через `display:block` и `::before`; все пять полей показываются как длинная вертикальная форма.
- Размеры зон нажатия переопределяются несколькими каскадами, поэтому экран нестабилен.
- Нижняя save-area выглядит как отдельная большая вложенная панель и расходует полезную высоту.

## Информационная архитектура

### Верхняя зона

- Заголовок и пояснение остаются компактными.
- Workbar содержит группу и дату слева, четыре счётчика справа.
- На mobile фильтры идут в одну компактную двухколоночную строку, если ширина позволяет; на узких экранах — две строки.
- Счётчики на mobile остаются одной сеткой 2×2 или 4×1 без горизонтального scroll.

### Desktop журнал

- Сохраняется таблица: ученик, статус, рейтинг, ДЗ, комментарий.
- Высота строки около `56px`; controls компактны, но зоны взаимодействия доступны.
- Статусы читаются как segmented control, выбранный статус выделяется цветом.
- Рейтинг остаётся пятизвёздочным.
- Комментарий не расширяет колонку и имеет ясный focus.

### Mobile карточка

- Каждая карточка — самостоятельный блок без имитации табличных строк.
- Header: имя и ID.
- Ряд статуса: три одинаковые кнопки на всю доступную ширину.
- Meta-row: рейтинг слева, переключатель ДЗ справа.
- Комментарий: один input на всю ширину.
- Подписи присутствуют только там, где без них значение неоднозначно.
- Карточки имеют один border, без вложенных карточек и лишних фонов.

### Сохранение

- Desktop: компактная sticky save bar высотой около `52px`, сообщение об изменениях и кнопка справа.
- Mobile: sticky bar у нижнего края; сообщение и кнопка в одной строке, при очень узкой ширине — компактные две строки.
- Disabled, pending, success и error визуально различимы.
- Большой пустой footer-блок удаляется.

## Архитектура реализации

- Бизнес-логику `AttendancePage` и repository flow не менять.
- В строке добавить явные структурные классы для student header, status section, rating/homework row и comment section.
- CSS модуля собрать в одном финальном attendance-блоке: base/desktop + один `@media (max-width:760px)`.
- Удалить только конфликтующие attendance declarations; другие модули не затрагивать.
- Не добавлять зависимости.

## Доступность

- Сохранить `aria-label`, `aria-pressed`, checkbox semantics и клавиатурный focus.
- Интерактивная зона основных mobile controls — не меньше `40px`.
- Цвет не является единственным индикатором выбранного статуса.
- Sticky bar не перекрывает последнюю карточку: список получает безопасный нижний padding.

## Тестирование

- Regression test проверяет структурные mobile hooks и доступные имена controls.
- Проверить изменение статуса, рейтинга, ДЗ, комментария и dirty/save states.
- Rendered QA: dark/light, desktop `1280×800`, mobile `390×844`.
- Проверить отсутствие horizontal overflow, clipping, console errors и framework overlay.
