# O‘quvchilar va Davomat: UX-доработка

Дата: 15.07.2026

## Цель

Сделать ежедневную работу администратора со студентами и посещаемостью быстрее, понятнее и безопаснее без смены общего визуального языка CRM и без изменения бизнес-правил.

## Общие принципы

- Сохранить компактный светлый интерфейс, текущую золотую акцентную палитру и типографику.
- Усилить визуальную иерархию, читаемость и понятность интерактивных элементов.
- Для всех действий обеспечить hover, focus-visible, active, disabled и loading состояния.
- Не менять поток данных `UI → TanStack Query → Repository` и контракты без отдельного согласования.
- Сохранить узбекский язык интерфейса, формат дат `DD.MM.YYYY` и валюту UZS.

## O‘quvchilar

### Desktop

- Сохранить таблицу как основной формат реестра.
- Сделать имя и ID главным визуальным ориентиром строки; вторичные данные оставить спокойнее.
- Добавить счётчики во вкладки статусов и понятный результат фильтрации.
- Улучшить поиск: очистка одним действием, корректное пустое состояние, сохранение доступной подписи.
- Сделать всю строку визуально отзывчивой при наведении, но не превращать её в скрытую ссылку.
- Сохранить меню действий, улучшить его позиционирование, клавиатурное управление и закрытие по `Escape`.
- Убрать риск случайной смены статуса: статус отображать как badge, изменение выполнять через меню действий с подтверждением для заморозки.
- Экспорт оставить mock-действием, но заменить системный `alert` на встроенное уведомление.

### Mobile

- Использовать компактные карточки с фиксированной иерархией: студент → статус/баланс → контакты → группы → действия.
- Основные данные показывать сразу, вторичные — без лишних рамок и вложенных карточек.
- Сохранить зоны нажатия не менее 40 px и исключить горизонтальный скролл.
- Кнопки добавления и экспорта оставить доступными без перегрузки заголовка.

## Davomat

### Desktop

- Сохранить табличный журнал и уменьшить визуальную растянутость строк.
- Объединить фильтры и сводку в компактную рабочую панель.
- Статусы сделать сегментированным контролом с устойчивой цветовой семантикой и понятным выбранным состоянием.
- Рейтинг и отметку домашнего задания сделать доступными с клавиатуры и снабдить явными focus-состояниями.
- Комментарий оставить быстрым inline-полем.
- Панель сохранения показывать как рабочее состояние: количество изменений, сохранение, успех или ошибка.

### Mobile

- Сократить высоту карточек: имя и код в шапке, затем статус, рейтинг, ДЗ и комментарий в плотной последовательности.
- Статусы должны помещаться без горизонтального скролла.
- Закрепить компактную панель сохранения снизу, не перекрывая последнюю карточку.
- Сводку сделать короткой и читаемой без горизонтальной прокрутки.

### Защита данных

- При смене группы или даты с несохранёнными изменениями показывать подтверждение.
- Не блокировать сохранение при валидных данных; во время запроса исключить повторную отправку.
- Ошибку сохранения показывать рядом с панелью действий, сохраняя введённые значения.
- Бизнес-правила списания баланса, уведомлений и идемпотентности не менять.

## Состояния

- Loading: стабильный skeleton/placeholder без скачка макета.
- Empty: объяснение причины и доступное следующее действие.
- Error: краткое сообщение и кнопка повторной загрузки.
- Success: ненавязчивое встроенное уведомление без системного `alert`.
- Dirty: явный индикатор несохранённых изменений.

## Архитектура

- Изменения ограничить страницами `StudentsPage`, `AttendancePage`, относящимися стилями и небольшими переиспользуемыми UI-компонентами при необходимости.
- Данные получать только через существующие TanStack Query hooks и repositories.
- Не добавлять зависимости, если текущих React, CSS и Lucide достаточно.

## Проверка

- Unit/component tests: поиск, вкладки, empty state, меню действий, dirty-state и подтверждение смены фильтра.
- Rendered QA: desktop 1440×900 и mobile 390×844.
- Проверить hover, focus-visible, dropdown, modal, изменение статуса, рейтинг, ДЗ, комментарий и сохранение.
- Запустить `pnpm test`, `pnpm lint`, `pnpm typecheck`, `pnpm build`.

## Вне текущего объёма

- Реальный экспорт CSV/PDF.
- Подключение backend endpoints.
- Изменение финансовых правил или API-контрактов.
- Редизайн общей навигации и остальных модулей.
